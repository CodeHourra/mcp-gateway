# MCP Gateway 安装与实机验证

适用：本次交付的 `0.1.5-dev`，Apple Silicon Mac、macOS 15 或以上。DMG 内含完整应用，运行不需要 Go、Node.js 或开发服务器；所选 stdio 上游自己的运行环境仍需安装。

本包仅使用本机 ad-hoc 签名，未做开发者签名和 Apple 公证。受控协议和主要 WebView 操作已有通过记录；下列安装、OS 菜单、真实服务/客户端和系统行为仍需在交付后验证。**完成打包不等于这些项目已经通过。** 每阶段完成后发回结果，我们再按实际情况指导下一阶段，不必一次测完。

## 第一阶段：安装、启动和菜单

1. **1.1 安装。** 从旧实例菜单退出后，打开本次 DMG，将 `MCP Gateway.app` 拖入“应用程序”。如已有同名旧应用，先保留旧副本。推出 DMG，再从 `/Applications/MCP Gateway.app` 打开。预期出现管理窗口、Dock 图标和菜单栏入口；首次使用可能是空服务列表。先固定安装位置，再配置客户端，避免其命令路径指向 DMG。
2. **1.2 菜单。** 等待网关状态变为“运行中”，点击菜单栏入口，依次检查“打开管理器”“设置…”“复制网关地址”。将地址粘贴到临时文本查看。预期前两项打开对应页面，地址与 Agent 接入页一致；新安装默认使用 `127.0.0.1:17840`。此时只验证地址显示，不用浏览器访问地址代替 MCP 调用。
3. **1.3 关窗和重开。** 点击窗口红色关闭按钮，再从菜单“打开管理器”；然后再次打开应用。预期菜单栏入口持续存在，关窗后 Dock 图标消失；重开时管理窗口与 Dock 图标恢复，不出现额外独立实例。实际后台调用留到 2.4 验证。
4. **1.4 主动退出。** 当前没有调用时，选菜单“等待调用完成后退出”。预期窗口与菜单栏入口消失；重新打开可恢复运行。此步不证明进行中调用的等待/取消行为，后续会用测试调用单独验证。

若首次打开提示开发者无法验证或未公证，确认它就是本次交付文件后，可在尝试打开后前往“系统设置 → 隐私与安全性 → 仍要打开”，再确认仅打开此应用。这是 Apple 提供的单应用处理方式，参见 [Apple 官方说明](https://support.apple.com/zh-cn/102445)。没有该按钮，或提示“已损坏”“包含恶意软件”时，先把提示原文发回排查；不要直接把所有拦截都当作未签名提示。

第一阶段反馈：DMG 文件名、Mac 芯片/macOS 版本、安装位置、1.1–1.4 各自“通过/失败/未测”，以及失败步骤的提示原文或遮盖隐私后的截图。若未能启动，先停在本阶段。

## 第二阶段：真实服务和客户端

先告诉我们可用于测试的服务名称、传输方式和客户端版本；连接地址、密钥和账号由你在本机填写。我们按现有条件选择不修改业务数据的测试工具。

1. **2.1 真实服务。** 在“服务”页先添加一个可用的本地 stdio MCP，命令和工作目录用绝对路径；再逐个加入静态认证远程 MCP，并覆盖 Streamable HTTP 和旧版 SSE。点击“测试连接”，从 Tools 读取参数并实际调用一个只读工具。预期服务“可用”、结果来自目标服务，活动能对上工具、时间和成功/失败；仅显示“配置已保存”不算连接通过。菜单“服务”停用/启用测试服务后，窗口状态和实际调用应一致；恢复连接后再检查“重连异常服务”。缺少某种服务时记为“未测”，由我们继续安排。
2. **2.2 真实 OAuth。** 使用可重复授权的测试服务/账号，按需填 Client ID/Scopes；验证“在浏览器中登录”、中途“取消登录”、重新登录、成功调用、“刷新授权”，以及退出应用后重开仍可调用。再由我们按提供方能力指导到期/失效、重新授权和“清除本地授权”。预期取消不假报成功，失效有提示且可恢复；清除仅移除本机授权，不撤销提供方网站授权。提供方无 refresh token 等能力差异要单独记录。
3. **2.3 五客户端。** 先打开“导入配置”，预期自动列出 OMP、Claude Code、Cursor、CodeBuddy、Codex 五个已知用户配置路径及各自状态；这一步只扫描，不应新增服务。对“发现配置”的来源点“检查预览”，确认应用自己的 `mcp-gateway connect` 接入条目显示为受阻并默认跳过，然后返回，不执行导入。再选你常用的一个客户端，并依次验证其余客户端；CodeBuddy 注明 CLI 或 CN 应用。在“Agent 接入 → 查看接入配置”核对目标文件、应用绝对路径、其他条目保留及变更范围，再“备份并应用配置”，重启对应客户端。当前接入可访问网关中全部已启用工具，确认范围后再应用。要求客户端通过 `mcp-gateway` 查找选定工具、读取参数并实际调用只读样例；在网关活动里核对同一目标和结果。预期是真实工具调用成功；配置检测成功或模型口头回答不能代替。若客户端询问权限，只批准本次测试所需项；模型账号登录或用量许可缺失就先记录并反馈。
4. **2.4 后台与并发。** 一个客户端调用通过后，关闭管理窗口，重复调用，预期仍成功。再让两个客户端同时执行可区分的测试输入；有状态服务使用专门的可恢复测试状态，由我们给出具体样例，预期目标和状态不串用。补测菜单“暂停新调用”/恢复、进行中测试调用的“等待调用完成后退出”和“立即停止并退出”；预期暂停拒绝新调用、恢复后成功，等待让既有调用完成，立即停止取消该调用并退出。

第二阶段反馈：步骤编号、服务名称/传输/认证类型、客户端及版本、操作时间、网关服务状态、实际工具名和无敏感结果摘要。有失败时从“活动 → 导出诊断”取得文件；预期提示完整保存路径，并在应用数据目录的 `diagnostics/` 中出现 JSON。分享前仍请检查服务名称等信息是否需要遮盖。

## 第三阶段：系统行为

1. **3.1 登录启动。** 保存其他工作后，记录原设置，打开“设置 → 登录时启动”并保存；在你方便时注销并重新登录。预期菜单栏自动出现，打开管理器后可完成 2.1 的同一只读调用。测试后按原偏好恢复开关并保存。注册成功提示本身不算实际登录启动通过。
2. **3.2 休眠唤醒。** 网关空闲时执行一次只读调用，正常休眠，再唤醒并重复调用。预期菜单/窗口状态一致、连接恢复且调用成功；记录休眠时长、唤醒后等待时间及是否需要手动重连。
3. **3.3 主题、选择控件和键盘。** 在应用依次选择 浅色、深色、跟随系统；跟随系统时再切换 macOS 外观，观察实际背景和文字，最后恢复原系统外观。退出重开，预期应用主题偏好保留。再检查添加服务的传输/认证、Tools 来源、导入方式/来源/处理方式，以及设置中的发现模式/日志天数：预期都显示为页面内单选项，没有系统下拉菜单，窄窗口下文字完整换行。用 Tab/Shift+Tab 移动焦点，方向键切换同一组选项，Enter/Space 操作按钮或开关，Esc 关闭已打开的确认框；预期焦点可见、数值保存正确。反馈异常页面和按键序列即可。

第三阶段反馈：3.1–3.3 的“通过/失败/未测”，测试前后状态和必要的遮盖截图。完成一项就记录一项，未执行项继续保留“未测”。

## 反馈和数据边界

可直接发送：`步骤｜通过/失败/未测｜时间｜预期与实际差异`。附 DMG 文件名和应用“设置 → 关于”的版本；校验值由交付消息提供。

**不要发送密钥、Token、Cookie、授权回调 URL、完整客户端配置或原始配置备份。** 账号登录始终在你的浏览器/客户端中完成。应用数据位于 `~/Library/Application Support/MCP Gateway/`；卸载、换包或排错时先保留该目录与钥匙串，不用删除配置来“重试”。应用移动后需重新预览并更新客户端命令路径。

已有检查和完整未测边界见 [验收报告](acceptance.md)，日常使用见 [README](../README.md)。
