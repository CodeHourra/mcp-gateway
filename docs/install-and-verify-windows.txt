MCP Gateway 安装与实机验证（0.1.12-dev，Windows x64）

适用：Windows 10 1809 或以上 / Windows 11，x64。应用自带网关核心，运行不需要 Go、Node.js 或开发服务器；stdio 上游自己的环境仍需安装。界面依赖系统自带的 WebView2 运行时，Windows 11 与已更新的 Windows 10 通常已包含；缺失时应用会提示安装。

安装
1.1 先退出正在运行的旧版（托盘图标右键退出）。解压 zip 到固定目录，例如 %LOCALAPPDATA%\Programs\MCP Gateway\，直接运行 mcp-gateway.exe。
1.2 本包未做代码签名，首次运行可能出现 SmartScreen“Windows 已保护你的电脑”。确认来源后点“更多信息→仍要运行”。没有该选项，或提示已被阻止/检测到威胁，先反馈原文排查。
1.3 应用数据位于 %APPDATA%\MCP Gateway\。覆盖解压新版本不会删除该目录中的服务配置、日志与客户端 token；排错时先保留它再重试，不要靠删配置。

第一阶段：启动与托盘
2.1 启动后应出现管理窗口和通知区域图标。检查托盘菜单“打开管理器”“设置…”“复制网关地址”，粘贴出的地址应与 Agent 接入页一致；新安装默认 127.0.0.1:17840。
2.2 关闭主窗口后网关应继续在托盘运行，重新打开不产生第二个实例。空闲时从托盘退出，进程应完全结束（任务管理器核对 mcp-gateway.exe 与 mcpproxy.exe 均退出）。此步不证明在途调用退出行为。
反馈：zip 文件名、Windows 版本、安装目录、2.1–2.2 通过/失败/未测及错误提示。

第二阶段：服务页面与操作反馈
3.1 服务页每张卡片只有一个展开入口。点击服务行展开，面板内出现“工具 / 连接与认证 / 活动”三个分段；需登录或连接失败的服务默认停在“连接与认证”，其余停在“工具”。可同时展开多个服务，卡片列表上方出现“全部收起”。
3.2 卡片头部在需要处理时直接给出“登录”“重新连接”或“编辑配置”，点击后按钮内出现进行中状态；结束后右下角出现结果提示。切换服务右侧开关应立即启用或停用该服务并给出提示。
3.3 服务筛选提供“全部 / 需处理”，计数随状态变化；筛选与搜索可叠加，结果为空时显示空状态。
3.4 “添加服务”与“编辑配置”打开模态表单；关闭有未保存修改的表单会先确认，放弃后焦点回到打开它的按钮。名称留空等校验错误显示在表单内。
3.5 “连接与认证”中确认地址、测试连接、重新连接、OAuth 登录/取消/清除，以及“删除服务”。删除先备份再删除，失败时错误显示在确认框内且不关闭。

第三阶段：真实服务和客户端
4.1 先加本地 stdio（命令/工作目录绝对路径，例如 node/npx 的完整路径），再静态认证远程服务，覆盖 Streamable HTTP/SSE。“测试连接”后实际调用只读工具。
4.2 用可重复授权的 OAuth 测试服务检查登录、取消、重新登录与清除；清除只移除本机授权，不撤销提供方网站授权。
4.3 打开“导入配置”，预期列出 OMP、Claude Code、Cursor、CodeBuddy、Codex 的已知路径及状态但不新增服务；对发现的来源预览后确认应用自己的 mcp-gateway connect 条目被阻止。再在 Agent 接入页预览并写入规则，重启客户端后确认可查找并执行只读工具。
4.4 关闭管理窗口后重复客户端调用；补测暂停/恢复、在途调用等待退出与立即停止。
反馈：编号、服务/传输/认证类型、客户端版本、时间、工具名、无敏感结果摘要。

第四阶段：外观与设置
5.1 检查浅色、深色、跟随系统。界面为半透明玻璃材质，文字对比度正常；系统禁用透明效果或提高对比度时应回退为不透明填充而不是变得不可读。
5.2 设置页修改任一选项后出现“有未保存修改”，保存按钮可用，左侧“设置”出现未保存圆点；保存后消失。“运行控制”中的“暂停新调用”立即生效。
5.3 Tab/Shift+Tab 移动焦点，方向键在服务行之间移动，Enter/Space 展开服务或操作控件，Esc 关闭对话框；切换页面后焦点落在页面标题。
注意：“登录时启动”在 Windows 上由系统启动项管理；若设置后未生效，记录 Windows 版本与提示原文。

统一反馈：步骤｜通过/失败/未测｜时间｜预期与实际差异。附 zip 文件名与“设置→关于”版本；校验值见发布说明。
不要发送密钥、Token、Cookie、授权回调 URL、完整客户端配置或原始备份。
