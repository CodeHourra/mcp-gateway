MCP Gateway 安装与实机验证（0.1.12-dev）

适用：Apple Silicon Mac，macOS 15 或以上。应用自带网关核心；运行不需要 Go、Node.js 或开发服务器，stdio 上游自己的环境仍需安装。
本包仅本机 ad-hoc 签名，未做开发者签名或 Apple 公证。以下项目交付后由我们指导你实测，打包完成不代表验收通过。每阶段发回结果后再继续即可。

第一阶段：安装、启动和菜单
1.1 先从旧实例菜单退出，再从 DMG 打开。打开 DMG，把 MCP Gateway.app 拖入“应用程序”；已有同名应用先保留旧副本。推出 DMG，从 /Applications/MCP Gateway.app 打开。预期管理窗口、Dock 图标和菜单栏出现。已有服务应先显示本地配置和待更新状态，随后自动更新；固定安装位置后再接入客户端。
1.2 网关“运行中”后检查菜单“打开管理器”“设置…”“复制网关地址”。预期页面正确，粘贴出的地址与 Agent 接入页一致；新安装默认 127.0.0.1:17840。
1.3 红色按钮关窗，再从菜单重开，并再次打开应用。预期菜单栏仍在，关窗后 Dock 图标消失，重开后窗口与 Dock 图标恢复，没有额外独立实例。
1.4 空闲时点“等待调用完成后退出”。预期窗口/菜单栏消失，重开正常。此步不证明在途调用退出行为。
首次提示开发者无法验证/未公证：确认本次交付来源后，可在尝试打开后用“系统设置→隐私与安全性→仍要打开”确认此应用。没有该按钮，或提示损坏/恶意软件，先反馈原文排查。

反馈：DMG 文件名、芯片/macOS 版本、安装位置、1.1–1.4 通过/失败/未测及错误提示。启动失败先停在这里。

第二阶段：服务页面与操作反馈
2.1 服务页每张卡片只有一个展开入口。点击服务行展开，面板内出现“工具 / 连接与认证 / 活动”三个分段；需登录或连接失败的服务默认停在“连接与认证”，其余停在“工具”。可同时展开多个服务，卡片列表上方出现“全部收起”。窄窗口下展开内容应可见且无横向滚动。
2.2 卡片头部在需要处理时直接给出动作：OAuth 服务显示“登录”，连接失败显示“重新连接”，其余静态认证服务显示“编辑配置”。点击后按钮内出现进行中状态，其他控件暂时不可用；结束后右下角出现结果提示。切换服务右侧开关应立即启用或停用该服务，并给出提示。
2.3 服务筛选提供“全部 / 需处理”，需处理计数随状态变化；筛选和搜索可以叠加，结果为空时显示空状态而不是空白列表。
2.4 点击“添加服务”或“编辑配置”打开模态表单。关闭有未保存修改的表单会先确认；放弃修改后焦点回到打开它的按钮。名称留空等校验错误显示在表单内，焦点移到错误提示。
2.5 “连接与认证”中确认地址、测试连接、重新连接、OAuth 登录/取消/重新登录/清除，以及“删除服务”都在同一分段内。删除先备份再删除，失败时错误显示在确认框内且不关闭。

第三阶段：真实服务和客户端
先提供可测试的服务名称/传输、客户端版本；地址、密钥和账号由你在本机填写。我们选择不改业务数据的工具。
3.1 先加本地 stdio（命令/工作目录绝对路径），再静态认证远程服务，覆盖 Streamable HTTP/SSE。“测试连接”后实际调用只读工具；预期服务可用、活动与结果对应。再用卡片开关停用/启用、恢复连接后重连异常服务，核对实际状态。缺少服务记未测。
3.2 用可重复授权的 OAuth 测试服务/账号，检查登录、取消、重新登录、实际调用、刷新和应用重启后调用；再由我们按提供方能力指导失效/重登/清除。取消不假报成功，异常能恢复。清除只移除本机授权，不撤销提供方网站授权；能力差异单独记录。
3.3 先打开“导入配置”，预期自动列出 OMP、Claude Code、Cursor、CodeBuddy、Codex 五个已知路径及状态，但不新增服务。对发现的来源点“检查预览”，确认应用自己的 mcp-gateway connect 条目受阻并默认跳过，然后返回、不导入。再选一个常用客户端，并依次验证其余客户端（CodeBuddy 注明 CLI/CN）。Agent 接入→配置接入或查看 / 更新配置：核对目标文件、应用路径、无关条目及范围，再备份并应用，重启客户端。接入能访问全部已启用工具，先确认范围。让客户端通过 mcp-gateway 查找工具、读参数、执行只读样例，并与网关活动核对。模型回答或配置检测不算工具成功；只批准测试范围。
3.4 关管理窗口后重复客户端调用，预期成功；两个客户端并发用不同输入，有状态样例由我们安排，预期目标/状态不串用。补测暂停/恢复、在途测试调用等待退出/立即停止：新调用按开关拒绝/恢复，等待完成旧调用，立即停止取消后退出。
反馈：编号、服务/传输/认证类型、客户端版本、时间、工具名、无敏感结果摘要。失败可从活动→导出诊断，按提示路径取得 diagnostics 下的 JSON；先检查服务名称等是否需遮盖。

第四阶段：外观、设置与系统行为
4.1 检查 浅色/深色/跟随系统；后者下切换 macOS 外观再恢复原值；退出重开检查偏好保留。界面为半透明玻璃材质：侧栏、工具栏、对话框和提示条应能看到背景渐变，卡片和按钮边缘有细高光描边；文字对比度正常，不出现发灰或读不清的文字。减少透明度、提高对比度或系统不支持背景模糊时，界面应回退为不透明填充而不是变得不可读。
4.2 设置页修改任一选项后应出现“有未保存修改”，保存按钮变为可用，左侧“设置”出现未保存圆点；保存后提示消失。“运行控制”中的“暂停新调用”立即生效，无需保存。
4.3 Tab/Shift+Tab 移动焦点，方向键在服务行之间移动，Enter/Space 展开服务或操作按钮/开关，Esc 关闭对话框；预期焦点可见，数值保存正确。切换页面后焦点应落在页面标题。
4.4 保存其他工作、记录原设置，开启并保存“登录时启动”；方便时注销/登录。预期菜单栏自动出现且原只读调用成功。之后按原偏好恢复开关。注册提示不算登录验证。
4.5 空闲时先调用，正常休眠、唤醒后再调用。预期菜单/窗口一致、连接恢复。记录休眠时长、恢复等待和是否手动重连。

0.1.12 变更
服务卡片由“展开工具 / 配置详情”两处互斥改为单一展开入口，面板内分段切换工具、连接与认证、活动；服务筛选分为“全部 / 需处理”；添加与编辑服务改为模态表单；操作结果统一为右下角提示，按钮内显示进行中状态；设置页显示未保存修改并把“运行控制”独立分区；整体改为 Liquid Glass 材质并保留不透明回退。
替换应用后若 Dock/访达仍显示旧图标，是 macOS 图标缓存按修改时间命中；重新复制一次应用或重新登录即可刷新，图标文件本身无需改动。

0.1.13 变更
新增“使用引导”页（渐进发现的调用方式说明与一键复制的 agent 规则 prompt）。新增更新检查：启动及每天查询 GitHub Releases（设置 → 关于可关闭）；发现新版本后可在设置中一键“更新到 X.Y.Z”：下载并按 .sha256 校验，通过后应用退出，由辅助进程替换并重新打开；失败时保留旧版本并记录到数据目录 update.log。应用所在目录不可写时改为打开安装包，需手动安装。
