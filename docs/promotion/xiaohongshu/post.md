## 正文（可直接复制）

同时用几个 AI 编程工具时，MCP 配置很容易散落在不同地方。加一个服务、换一次连接信息，就得来回找配置文件。

所以我最近做了一个 macOS 小工具：MCP Gateway 🌿

想解决的事情很具体：把 MCP 服务集中管理，给多个客户端提供统一的接入入口。

目前做了这几件事：

① 服务集中看
在一个窗口里管理服务、连接与认证，查看工具目录和连接状态。关掉主窗口后，网关继续在菜单栏运行。

② 工具按需找
渐进模式下，先检索工具、查看参数，再执行调用；也保留普通聚合模式，按场景选择。

③ 改配置先预览
已有配置可以导入，确认变更后再写入；写入前有备份，保留恢复入口。

④ 调用可以直接调试
查看网关入口实际暴露的工具，填写 JSON 参数，检查完整结果与错误信息。

目前是 0.1.10 开发版，面向 Apple Silicon / macOS 15+。已有多客户端配置适配，真实客户端与真实服务的兼容性还在继续验证。

你现在最头疼的是反复配 MCP、工具太多，还是连接失败不好排查？评论区聊聊，我会继续根据实际使用问题打磨。
